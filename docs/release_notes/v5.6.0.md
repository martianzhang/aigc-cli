# Release Notes v5.6.0

> 适配 DeepSeek 2026-11-13 发布的「全家桶应用 API」：OCR、ASR、TTS 走独立 tools 端点，
> 并新增内置 `deepseek` Provider。无破坏性变更。

## Highlights

### 🐋 DeepSeek OCR / ASR / TTS

DeepSeek 的 chat / 视觉仍兼容 OpenAI 协议，但新开放的三个工具接口不是：

| 能力 | 端点 | 协议 |
|---|---|---|
| OCR | `POST /v1/tools/ocr` | multipart（`purpose` 必须在 `file` 前） |
| ASR | `POST /v1/tools/asr` | multipart |
| TTS | `POST /v1/tools/tts` | JSON → 音频流 |

之前这些能力会落到 `/chat/completions` 或 `/audio/*`，调用失败。现在
`type: deepseek` 或 `api.deepseek.com` 会自动路由到正确端点。

```bash
export DEEPSEEK_API_KEY=sk-xxx

aigc-cli ocr scan report.pdf --provider deepseek
aigc-cli ocr scan report.pdf --provider deepseek --purpose rich_layout_recognition
aigc-cli audio speak --provider deepseek -i "你好，我是 DeepSeek。" --voice stella
aigc-cli audio transcribe --provider deepseek -i speech.wav
```

也可以写进配置：

```yaml
providers:
  deepseek:
    type: deepseek          # 省略 base_url 时默认 https://api.deepseek.com
    api_key: "sk-xxx"

defaults:
  ocr:
    provider: deepseek
  audio:
    speak:
      provider: deepseek
    transcribe:
      provider: deepseek
```

### 📄 OCR：整份文档服务端识别

- `ocr scan` 直接把 PDF / DOC / DOCX / PPT / PPTX / 图片上传到 `/v1/tools/ocr`；
- 新增 `--purpose text_recognition`（默认）与 `rich_layout_recognition`；
- 逐页输出，保留 `<|ref|>` / `<|box|>` 标记与 0–1000 归一化坐标；
- 支持最多 100 MiB / 1,000 页；
- `--model` / `--prompt` / `--pages` / `--engine` / `--lang` / `--json` 等参数对
  该端点无效，显式使用会打印忽略提示；
- 输出仍为 `<name>.md`，`-o -` 打印到 stdout。

### 🔊 TTS / ASR：专用参数与限制

TTS：

- 音色 `stella`（女声，默认）/ `tide`（男声），对应 `--voice`；
- 格式 `wav`（默认）/ `pcm`，对应 `--format`；
- 单次最多 10,000 计费字符 / 64 KiB，最长 30 分钟音频；
- `--model` / `--speed` / `--instructions` 不适用，自动忽略并提示；
- 配置里遗留的本地音色或 `mp3` 格式会回退到 DeepSeek 默认值，不会中断请求。

ASR：

- 仅接受 16 位 PCM WAV 或 Ogg Opus，最大 8 MiB / 120 秒；
- 语种自动识别，`--model` / `--language` 不生效；
- 上传前做扩展名与大小校验，错误信息直接指出可用格式；
- base64/stdin 输入不支持，需传本地文件。

### 👁 图像理解

DeepSeek 视觉仍走 OpenAI 兼容 `image_url`；Provider 未配置 model 时自动使用
`deepseek-flash`，`vision` / `detect` 无需额外参数。

### 🔌 MCP

`generate_speech` 与 `transcribe_audio` 同步支持 DeepSeek；Provider 仍只能从
`config.providers` 白名单引用。

- 新增 DeepSeek 域名检测、`type: deepseek` 内置 endpoint、`--provider deepseek` 别名；

- 更新中英文 OCR、Audio、API Reference、配置示例与 README。

## 升级提示

- 无破坏性变更，直接覆盖二进制即可。
- 已有的 `deepseek` 搜索配置（`search.providers.deepseek`）与本次生成侧
  `providers.deepseek` 属于不同命名空间，可继续共存。
- DeepSeek 不提供图像/视频生成；`image` / `video` 命令请继续使用其他 Provider。
- DeepSeek Files API 的 `file_id` 文档问答、TTS WebSocket 流式合成暂未纳入。
