# Release Notes v3.9.0

> 本版聚焦**图像超分辨率**：新增 `upscale` 命令——本地 **Real-ESRGAN / Real-CUGAN / Swin2SR** ONNX 模型，2x/4x 放大、完全离线；同时根治了**图片解码崩溃**问题（畸形图不再让进程 panic）。另修复 OpenRouter 视频任务的 job 文件清理。

## Highlights

### 🔎 新增 `upscale`：本地 AI 图像超分（2x / 4x）

新增 `aigc-cli upscale` 命令，用本地 ONNX 模型把图片放大 2x/4x（合成细节，不是插值拉伸）。复用 `background` / `depth` / `ocr` 同一套 ONNX Runtime，**完全离线、无需 API Key**。

```bash
# 首次：下载 ONNX Runtime + 默认模型
aigc-cli upscale init
aigc-cli upscale init --list          # 查看模型与许可证

# 放大（默认通用 4x → <文件名>_upscaled.png）
aigc-cli upscale -i photo.jpg
aigc-cli upscale -i art.png --model real-cugan-2x
aigc-cli upscale -i photo.jpg -o photo_4x.png --scale 4
```

- **分块（256×256 / 16px 重叠）+ 羽化融合**：大图内存可控、块间无可见接缝，任意尺寸都能处理。
- 输出为 PNG（模型不输出 alpha 通道）。
- 同时提供 MCP 工具 `upscale` 与 Chat 工具 `upscale`（离线可用）。

### 🛡️ 图片解码不再崩溃 / 不再刷 stderr

`gen2brain/jpegli` 会在 `init()` 里注册一个 JPEG 解码器，**覆盖标准库的 `image/jpeg`**，遇到畸形 JPEG 时以 wasm panic（`unreachable`）冒泡，直接崩掉整个进程，并在 stderr 打印 `libjpegli` 的 `unexpected EOI marker` 等噪音。

- 改为使用 fork **[`github.com/martianzhang/jpegli`](https://github.com/martianzhang/jpegli)**（`v0.4.2-aigc.1`，仅移除该解码器注册，编码器不变）：**JPEG 解码回落标准库**（返回错误、不 panic、无噪音），**JPEG 编码仍用 jpegli**（同画质体积优势保留）。
- `detect` 全链路（`service/detect`、`cli/detect`、`internal/detect`、`internal/onnx`）改用 `imgcodec` 的 panic-safe `Decode/DecodeConfig`，同时兜住其余 wasm 解码器（webp / avif / jpegxl）在畸形输入上的 panic。

## 验证

- `make fmt` / `make build` / `make test` / `make lint`（0 issues）全部通过。
- `upscale`：7 个模型逐个实测可下载并跑通（含非 64 倍数尺寸、多瓦片大图无接缝）。
- 解码稳健性：4 个畸形 JPEG 修复前必崩、修复后全部优雅处理且无 stderr 噪音；正常图回归通过。
- 画质/体积：同画质（等 PSNR）下 jpegli 编码比标准库小约 1.2×–2.1×（故保留 jpegli 编码）。

## 兼容性说明

- **无破坏性变更**。
- `upscale` 首次使用需 `aigc-cli upscale init`（下载 ONNX Runtime + 模型；遵循配置的 `http_proxy`）。
- 构建依赖公开 fork `github.com/martianzhang/jpegli`（`go.mod` 中 `replace`），无需本地特殊配置。
- 模型权重保留各自上游许可证：Real-ESRGAN（BSD-3-Clause）、Real-CUGAN（MIT）、Swin2SR（Apache-2.0）。
