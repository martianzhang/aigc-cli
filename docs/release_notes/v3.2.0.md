# Release Notes v3.2.0

> `--json` 透传版本。核心是把 `--json` 从「按 CLI 已建模的字段解析」改为**逐字转发**：用户写什么，就发给 API 什么。由此无需改代码即可使用任意厂商的任意参数（LoRA、seed、steps、厂商私有字段），并顺带补齐 ModelScope 的图生图与真实错误信息。

## Highlights

### 📨 `--json` 现在是逐字透传的请求体

此前 `--json` 会被解析进 `types.GenerateRequest`，**未建模的字段被静默丢弃**（Go 的 `json.Unmarshal` 默认忽略未知字段），因此 `seed` / `steps` / `loras` 这类参数写了也没用。

现在 `--json` 的原文字节会**原样**成为请求体，对所有 provider 生效；CLI 只做四件必要的事：补认证头、补协议头（如 `X-ModelScope-Async-Mode`）、轮询、下载。本地图片路径仍会自动转 data URI（APIMart 走上传）。

```bash
# ModelScope：单个 LoRA（字符串形式）+ 固定 seed
aigc-cli image --provider modelscope --json '{
  "model": "krea/Krea-2-Turbo",
  "prompt": "a young woman standing by a bright window",
  "loras": "yan303145427/krea2-Cc-FY-portrait",
  "seed": 12345,
  "steps": 30,
  "size": "1104x1472"
}'

# 多个 LoRA（id→权重 map）
aigc-cli image --provider modelscope --json '{
  "model": "krea/Krea-2-Turbo",
  "prompt": "a young woman standing by a bright window",
  "loras": {
    "yan303145427/krea2-Cc-FY-portrait": 1.0,
    "yan303145427/krea2-Cc-Ins-portrait": 1.0
  },
  "seed": 12345,
  "steps": 30,
  "size": "1104x1472"
}'
```

**权重不做任何归一化** —— 写 `1.0/1.0` 就发 `1.0/1.0`（ModelScope 接受总和不为 1 的权重，两者均为满强度）。想按 7:3 混合就写 `0.7/0.3`。

### 🎛️ ModelScope：LoRA、图生图与真实错误

- **LoRA**：经 `--json` 的 `loras` 字段传入。**不能把 LoRA 仓库 ID 当 `--model`** —— 那样 ModelScope 会静默回退到底模，出图与该 LoRA 完全无关（不报错，极易踩坑）
- **图生图**：本地 `--image-url` 自动转 base64 Data URI，以 `image_url` 字段提交
- **错误信息**：任务失败时读取 API 的 `errors.message`，不再显示笼统的 `unknown error`（例如内容审核拦截会给出真实原因）

### 🧪 如何验证参数真的传到位

同一条 `--json` 跑两次，**两次输出哈希必须一致**。不一致即说明参数被上游忽略。

## Internal

- `types.GenerateRequest` 新增 `RawJSON json.RawMessage`，并实现 `MarshalJSON`：有 `RawJSON` 时原样输出，否则回退到既有字段序列化（flag 路径行为不变）
- `parseJSONInput` 保留 `--json` 原文
- 新增 `resolveRequestImages` 共享图片解析（typed 路径走 APIMart 上传、verbatim 路径就地改写），`runImageGenerate` 与 `GenerateAndSave` 共用
- 新增 `resolveRawImagePaths` / `resolveRawImageValue`，按嵌套键路径（`image_url` / `image_urls` / `mask_url` / `extra_body.image`）改写本地路径
- 移除上一轮尝试的 `Seed` / `Steps` / `LoRAs` 显式字段与 LoRA 权重归一化 —— 透传已覆盖，且归一化会静默削弱用户意图

## 验证

- `make fmt` / `make build` / `make test`（42 包全绿，0 失败）
- 端到端实测：
  - **ModelScope**：同 `--json` 两次输出 sha256 一致 → seed 确实传到位；单 LoRA / 双 LoRA 经 CLI 发出的字节与手写直连 API **哈希完全一致**
  - **Agnes**（免费，用于回归其他 provider）：文生图 / 图生图 / `--json` 透传 / `--json` + `extra_body.image` 本地路径，四条路径均通过
- 新增测试全部**离线**，无网络依赖、无付费调用

## 兼容性说明

- **行为变更**：`--json` 中未建模的字段**不再被静默忽略**，而是原样转发。若此前依赖「多写的字段会被丢弃」，现在它们会到达 API（键名写错将由 API 报错，而非无声失效）。
- flag 路径（`--model` / `--prompt` / `--image-url` 等）行为不变；`RawJSON` 仅在 `--json` 场景下设置。
- Agnes 的 `extra_body.image` 本地路径此前不会被解析，本版一并修复。

> 版本号说明：新增 `--json` 逐字透传与 ModelScope LoRA / 图生图能力，属向后兼容的功能新增，故以 minor 号发布。
