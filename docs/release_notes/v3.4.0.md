# Release Notes v3.4.0

> 一次围绕 `--json` 输入体验的功能版：`--json` 不再吞掉 CLI 参数，支持 JSONC 注释与尾随逗号，`--provider` 有了 `-P` 简写；并顺带修掉一批既有缺陷。

## Highlights

### 🔗 `--json` 与 CLI 参数联动（CLI 参数 > JSON 输入）

以前只要传了 `--json` 就会忽略所有 CLI 参数；现在**显式指定**的参数会覆盖 JSON body 中对应的键，未涉及的键（包括 CLI 未建模的厂商私有键，如 `loras`/`seed`/`steps`）原样保留；**不带任何参数时 body 仍逐字节原样发送**。于是可以把稳定参数放进 JSON，临时只改一个提示词：

```bash
aigc-cli image --provider modelscope --json downloads/prompt.json --prompt "低角度丝袜广告"
```

覆盖范围：`image`、`video`、`chat`、`midjourney`（全部 16 个支持 `--json` 的子命令）、`music`（**后端感知** —— 覆盖写入的是当前后端的原生键：APIMart suno / flowmusic、OpenRouter Lyria、百炼 fun-music）。

- 合并由共享的 `service.MergeJSONOverlay` 完成：空集合直接返回原字节；`UseNumber` 解码 + 不转义 HTML，未触碰的数字（大整数、`1.0`）与字符串保持原样。
- 行为类参数（`--dry-run`、`--preview`、`--provider`、`--api-key` 等）永不写进 body。

### 🧩 `--json` 支持 JSONC

`--json` 现在同时接受 JSONC：`//` 行注释、`/* */` 块注释、`}`/`]` 前的尾随逗号、开头的 UTF-8 BOM 都会在解析前剥离。

- **字符串感知**：字符串里的 `//`、`/*`（例如 `"https://host/a//b"`）原样保留，不会被误当注释截断。
- 不含注释的严格 JSON **逐字节不变**，不影响「原样发送」的既有保证。
- 文件、内联、stdin 三种来源都生效；`--json "$(cat request.jsonc)"` 也可用。

```jsonc
{
  // 结构化参数可以写注释
  "model": "krea/Krea-2-Turbo",
  "prompt": "低角度丝袜广告",
  "loras": { "yan303145427/krea2-Cc-FY-portrait": 1.0 }, // 尾随逗号也可以
  "size": "1080x1920",
}
```

### ⌨️ `--provider` 新增 `-P` 简写

`--provider` 是全局持久化 flag，会被所有子命令继承，因此简写必须与任何子命令都不冲突。`-p` 已被 `--prompt` / `--preview` 等占用，而 `-P`（pflag 区分大小写）全仓库无人使用：

```bash
aigc-cli image -P modelscope --json request.json
```

### 🐛 修复

| 问题 | 说明 |
|---|---|
| `--json` 路径不存在 | 现在明确报 `file not found: <路径>`，不再抛 JSON 解析错误 |
| midjourney `--index 0` 被吞 | task-action 子命令改用 `Changed` 判定，`--index 0` 生效 |
| `MJRemixRequest.Index` | 补 `omitempty`，未设置时不再序列化为 `0` |
| image 本地图片保真 | `resolveRawImagePaths` 改用 `UseNumber` + 不转义 HTML，数字与转义不再被打回 `float64` |
| video `--json` 分支 | 统一设置 `RawJSON`，与其它命令一致（未知键不再被丢弃） |

### 🧹 其它

- 移除内置的 agent SKILL 定义（`skills/`），改由外部 skill 机制提供。

## 验证

- `make fmt` / `make build` / `make lint`（0 issues）/ `make test`（全部包通过）
- 以 `--dry-run` 实测：参数覆盖生效、厂商私有键保留、无参数时逐字节原样、字符串内 `//` 保留、JSONC 文件/内联/stdin 均可解析
- 全命令树简写冲突检查（顶层命令 + midjourney 全部子命令）无 panic

## 兼容性说明

- **无破坏性变更**：既有「`--json` 不带参数」的行为完全不变，仍逐字节原样发送。
- 唯一语义微调：以 `//` 或 `/*` 开头的值现在被当作**内联 JSONC**，而不再当作文件路径（仅影响「不存在、且以注释开头」的路径）。
- 新增能力均为向后兼容：`-P` 是新增简写，JSONC 是放宽输入。
