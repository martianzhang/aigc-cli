# Release Notes v4.6.0

> 以「chat TUI 体验」为主轴的一次功能版本：消息渲染与输入框彻底重做、终端原生多行输入、
> 工具调用卡片与执行确认、联网引用展示、真正可用的中断；同时统一了 `--prompt` 输入方式，
> 新增 `models --list-providers`，并修掉流式 TTS 的 WAV 头问题。**含 3 处不兼容变更**（见文末）。

## Highlights

### 💬 chat TUI：重做消息区与输入框

```
💬 Chat with AI  —  Model: deepseek-v4
     ___       ____      ______     _____
    /   |     /  _/    / _____/    / ___/      ← 欢迎 logo 常驻滚动区
  ...
  💬  Type a message to start chatting

┃ You:                                        ← 蓝色左边条覆盖整块消息
┃ 1+1等于几？
┃ Assistant:                                  ← 绿色左边条
┃ 2
🛠️  bash go test ./...                        ← 工具卡片：参数 + 结果
  ✓ ok  github.com/… 0.42s

────────────────────────────────────────────  ← 分隔线
┃ Enter: send · Alt/Shift+Enter: newline      ← 输入框（随内容 1–5 行）
● Ready | Provider: apimart | Model: deepseek-v4
```

- 欢迎页 logo 不再在第一条消息后消失，可随时向上滚动查看；
- 消息整块带左边条 + 悬挂缩进，多行内容/代码块对齐不再错位；
- 模型流式输出首尾的空行会被裁剪，回复不再多出 1–2 个空行；流式阶段与完成后的样式一致，不会「跳一下」；
- 长行（中文、URL）按终端宽度折行且保留颜色，markdown 不再固定 80 列；
- 输入框内容空时只占 1 行，随草稿增长到 5 行，之后在框内滚动；与对话区之间新增一条浅蓝分隔线；
- header + 消息区 + 分隔线 + 输入框 + 状态栏严格等于终端高度（窄终端、超长草稿、确认框都不再溢出或留白）；
- `↑`/`↓` 在多行草稿内移动光标，回到首行/末行时才翻阅命令历史。

### ⌨️ 多行输入：Shift+Enter / Alt+Enter / Ctrl+Enter

之前只有 `Ctrl+J` 可靠，Alt+Enter 常常直接发送。现在 TUI 启动时会开启 xterm
`modifyOtherKeys`（`CSI > 4 ; 2 m`）并在退出时恢复，再把这些扩展按键序列翻译回终端原有编码：

| 按键 | 行为 |
|---|---|
| `Enter` | 发送 |
| `Shift+Enter` / `Alt+Enter` / `Ctrl+Enter` | 换行 |
| `Ctrl+J` | 换行（所有终端都可用） |

支持 xterm / iTerm2 / kitty / WezTerm / Ghostty 等实现了该协议的终端；macOS 自带
Terminal.app 不支持上报修饰键，请用 `Ctrl+J`，或把 Option 设为 Meta 后用 `Alt+Enter`。

### 🛠️ 工具调用可视化与执行确认

- 每次工具调用显示一行参数摘要（bash 命令、read/grep/find 参数、write/edit 目标与增删行数、MCP 工具的紧凑 JSON）；
- `write` / `edit` 直接展示 `+/-` diff 预览（在 agent goroutine 里计算，不阻塞界面）；
- 超过 20 行的输出自动折叠，`Ctrl+O` 展开/收起最近一次；
- 新增配置 `defaults.chat.confirm_tools`（Go 正则列表，匹配 `<tool> <target>`），默认拦截 `bash` / `write` / `edit`：
  `y` 本次允许、`a` 本进程总是允许、`n` 拒绝，`Esc` 拒绝并中断本轮；拒绝会返回给模型，让它换个做法继续；
- `--message` / 管道输入不触发确认；`!command` 与 `/<tool>` 视为用户显式意图，同样不询问。

### 🔗 联网引用（citations）

Provider 侧联网搜索的引用现在会在 TUI 回复下方以 `Sources:` 展示（默认 10 条，`-v` 全量）：URL 可点击（OSC 8），标题可选中复制。

### ⛔ 真正可用的中断

`Esc` / `Ctrl+C` 现在会取消正在进行的 HTTP 请求、杀掉正在跑的 `bash`/MCP 工具，并用 turn id 丢弃该轮的迟到数据；已生成的部分回复保留并标记 `[interrupted]`。
`Ctrl+C` 在处理中=中断、空闲时=退出；`Ctrl+D` 在输入框有草稿时忽略，避免误删。

### 🧾 `models --list-providers`

不联网、不需要 API key，直接列出已配置的 provider、类型、host 和是否已配置 key（从不打印 key 本身）：

```bash
aigc-cli models --list-providers
```

解析不到 API key 时，`chat` / `image` 等命令也会先打印候选 provider 再报错，方便定位配置问题。

### 🎛️ 统一 `--prompt` / `-p` 输入

```bash
aigc-cli chat -p "解释一下这段代码" -p @notes.md   # 可重复，按命令行顺序拼接
aigc-cli audio speak -p "你好" -o hi.mp3          # --input 的别名
aigc-cli music generate -p song.md               # 传文件路径则读取文件内容
```

`--message` / `--prompt` 的值若是一个已存在的文件路径，会读取文件内容发送。

### 🔧 audio：兼容流式 WAV 头

Ollama 等流式 TTS 在写完头部时还不知道长度，RIFF/data 大小会写 `0xFFFFFFFF`。现在把它视为
「读到 EOF 为止」，并在保存 `.wav` 时重写正确长度，严格播放器也能正常打开（修复 `--play`
时的 `read samples: unexpected EOF`）。

## 不兼容变更

### 1. 移除有歧义的短参数

| 命令 | 移除 | 改用 |
|---|---|---|
| `background` | `-p`（preview） | `--preview` |
| `depth` | `-p`（parallel） | `--parallel` |
| `models` | `-p`（price） | `--price` |
| `chat` | `-i`（interactive） | `--interactive` |

长参数行为不变。

### 2. `audio sfx` 的专用开关改为 `--inject-json`

`--loop` / `--influence` / `--seed` / `--no-normalize` 已删除，统一走厂商字段透传（本地模型读取
`steps` / `sigma_max` / `seed` / `normalize`，未知键会报错）：

```bash
aigc-cli audio sfx -P local -m stable-audio-open-small -i "door slam" -d 0.8 \
  --inject-json '{"seed":42,"steps":8,"normalize":true}'
```

MCP 的 `generate_sfx` 同步调整：`loop` / `influence` / `seed` / `normalize` 换成 `inject_json`。

### 3. TUI 按键语义

- `Esc` / `Ctrl+C` 在处理中会真正中断当前轮（不再是忽略或直接退出）；
- `Up`/`Down` 在多行草稿中优先移动光标，到边界才翻阅历史；
- 默认会要求确认 `bash`/`write`/`edit` 调用；不需要时在配置里写 `confirm_tools: []`。

## 升级提示

- 如果脚本里用了上面被移除的短参数，请改成对应的长参数；
- `audio sfx` 的自定义参数请迁移到 `--inject-json`；
- 想恢复「工具调用不问直接执行」，把 `defaults.chat.confirm_tools` 设为 `[]`；
- `Shift+Enter` 依赖终端上报修饰键；不支持的终端请用 `Alt+Enter`（需要 Option as Meta）或 `Ctrl+J`。
