# Release Notes v3.10.0

> 本版聚焦**图生图的正确性**：OpenAI 家族端点（原生 OpenAI / Azure OpenAI / OfoxAI）此前把参考图塞进 `/images/generations` 的 `image_urls`，而该端点没有这个字段，图片被**静默丢弃**——表现为「输入一张图、输出却完全无关」。本版按域名自动改走 **multipart `POST /images/edits`**，并附带 OfoxAI 的 provider pin。同时把 `--edit` 扩展为通用编辑协议开关、修复了 `--size` 提示在内容安全报错上的误触发。

## Highlights

### 🖼️ OpenAI 家族图生图自动走 multipart `POST /images/edits`

OpenAI 原生、Azure OpenAI 与 OfoxAI（`api.ofox.ai` / `api.ofox.run` / `api.ofox.io`）的 `POST /images/generations` **没有参考图字段**，此前的顶层 `image_urls` 会被忽略，只按 prompt 出图。现在 CLI **按域名自动识别并切换到 multipart edits，无需任何开关**：

```bash
# OfoxAI：本地文件作为 image 文件部件上传，model/prompt/size/quality 作为表单字段
aigc-cli image -P ofox -m openai/gpt-image-2.5-sunburst \
  -i photo.png -p "像3岁小朋友的思考方式用蜡笔重新绘制" --dry-run
```

```text
curl -X POST https://api.ofox.ai/v1/images/edits \
  -H "Authorization: Bearer ...xxxx" \
  -H "X-OfoxAI-Provider-Type: openai" \
  -F "model=openai/gpt-image-2.5-sunburst" \
  -F "prompt=像3岁小朋友的思考方式用蜡笔重新绘制" \
  -F "size=1024x768" \
  -F "image=@photo.png"
```

- 本地文件作为 multipart `image` 文件部件上传；远程 URL、data URI、裸 base64 会在发送前下载/解码为文件部件。
- 支持 `--mask-url`（作为 `mask` 文件部件）。纯文生图（不带 `--image-url`）仍走 `/images/generations` 同步路径。
- 该路径对**所有** OpenAI 家族域名生效；接受顶层 `image_urls` 的兼容中转行为不变。

### 🔓 OfoxAI 自动附带 `X-OfoxAI-Provider-Type: openai`

ofox 的 `openai/gpt-image-*` 由 `azure_foundry`（审核**更严**）与 `openai`（**更宽松**）两家承载，不 pin 时按权重分流可能落到 azure_foundry，把正常 prompt 误判成 `content safety policy` 拒绝。`/images/edits` 是 multipart、无法用 `extra_body`，只能用请求头 pin——CLI 已自动加上（`--dry-run` 可见）。

### ✏️ `--edit` 扩展为通用「编辑协议」开关

`--edit` 不再是 APIMart 专用，而是按 provider 选择编辑协议：

| Provider | `--edit` 走的协议 |
|---|---|
| APIMart | Grok Imagine 1.5 Edit（异步），默认模型 `grok-imagine-1.5-edit-apimart` |
| OpenAI 家族（OpenAI / Azure / OfoxAI） | multipart `POST /images/edits` |
| ZeekAI | JSON `POST /images/edits` |

可用于**不依赖域名自动识别**时强制走编辑协议（例如自定义中转）。

### 🧩 `--edit --json`：JSON 键值 → multipart 表单字段

配合 `--edit` 时，`--json` 对象的键值会映射为 multipart 表单字段（文件仍来自 `-i`），从而能传厂商私有字段：

```bash
aigc-cli image -P ofox --edit \
  --json '{"model":"openai/gpt-image-2.5-sunburst","prompt":"...","quality":"high","input_fidelity":"high"}' \
  -i photo.png
```

- 标量（string/number/bool）→ 一个字段；字符串数组 → 重复字段；嵌套对象 / `null` / 空串 → 跳过；文件类键（`image`/`images`/`image_url`/`image_urls`/`mask`/`mask_url`）不转为字段。
- **单独的 `--json`（不带 `--edit`）行为不变**：逐字透传走 `/images/generations`。

### 🐛 `--size` 提示不再在内容安全报错上误触发

`imageFailureHint` 之前的兜底是「只要是 400 且设了 `--size` 就提示」，导致内容安全/审核类报错也被硬塞 `--size` 建议。现在新增「明确非尺寸错误」关键词排除（content safety / moderation / 内容安全 / 违规…）：审核报错不再提示，真正的尺寸错误（如 `Invalid size ... Expected WIDTHxHEIGHT`）照常提示。
