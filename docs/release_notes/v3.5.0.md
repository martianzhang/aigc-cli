# Release Notes v3.5.0

> 一次功能与 CLI 体验并重的版本：`chat` 支持 OpenAI Responses API，`image --size` 支持 `<tier>@<ratio>` 复合写法，`ideas` 新增 civitai 源；同时统一了 `--dry-run` / `--output`，并移除了本地命令的 JSON 输出。

## Highlights

### 🤖 `chat` 支持 OpenAI Responses API

Provider 现在可通过配置 `type` 选择线协议：

- `openai`（默认）/ `openai_chat_completions` → `POST /v1/chat/completions`
- `openai_responses` → `POST /v1/responses`

原因：推理模型（如经 OpenLux 提供的 GPT-6）在 `/v1/chat/completions` 上带 function tools 会因 `reasoning_effort` 报 HTTP 400，而 Responses API 支持带推理的 tools。

实现包含 messages → input/instructions 转换、扁平 tool 形状、Responses SSE 解析、`call_id` 到 tool-call 的映射、`max_output_tokens` 映射与 dry-run curl。未知/旧协议的回退行为不变。

### 🖼️ `image --size` 支持 `<tier>@<ratio>` 复合写法

`--size` 现在接受 `2K@16:9` 这类组合，在 `buildImagePlan` 中一次性归一化，CLI / MCP / chat 以及原样转发的 `--json` body 都能看到 `Size` + `Ratio`：

```bash
aigc-cli image --prompt "..." --size 2K@16:9
```

- OpenRouter 图片请求由 `Ratio` 发出 `aspect_ratio`；ratio 会丢弃冲突的显式像素尺寸（OpenRouter 拒绝二者并存）。
- Agnes 的 ratio 改为 move 进 `extra_body`。

### 🔎 `ideas` 新增 civitai 数据源

Civitai 没有 prompt 搜索端点，因此用两步近似：先用 `/api/v1/models?query=` 解析关键词到模型，再取各模型最新版本的 `/api/v1/images?...withMeta=true` 读取 `meta.prompt`。

- 并发查询模型，单个模型失败不影响其它结果。
- 免密钥，默认排除 NSFW；按 prompt 文本去重。
- 在线检索超时 5s → 12s（覆盖两次往返）。

配合既有的多源合并（`local` / `aipromptslibrary` / `prompts.chat` / `openart`）与 FuseRRF 排序。

### 🖥️ 预览按终端自动缩放

内联预览（sixel / iTerm2）不再按硬编码 80 列渲染，而是读取真实终端尺寸并缩放到 60%；**只缩不放**，小图保持原始尺寸。缩放改用 Catmull-Rom。并修复了 `image --preview` 与 `preview` 命令渲染位置不一致的问题。

### ⌨️ CLI 体验统一

- `--dry-run` 改为 `midjourney` / `music` / `audio` 父命令的持久 flag，所有子命令统一继承（此前 MJ task-action 子命令不支持）。
- `--output` 统一为全局 flag 并新增 `-o`；移除 `background` / `depth` 的局部 `--output`，修复 background 本地/在线路径写入目录不一致的问题。
- `--json` 只表示"输入请求 JSON"：移除 `detect` / `ocr scan` / `ideas` / `background` 的 JSON 输出。

### 🔒 安全

`config.yaml`（API key）、其 `.bak`、以及加密 vault 文件此前以 `0644` 写入，同主机其它用户可读。现统一用 `fsutil.WritePrivate` 以 `0600` 写入（并收紧既有文件），vault 目录 `0700`。

## 修复

| 问题 | 说明 |
|---|---|
| `chat --message` 重复发送 | 非交互 `--message` 路径先后调用 `sendChatRequest` 与 `runAgentLoop`，同一历史发两次、答案打印两次；现只走 agent loop |
| `chat --no-stream` 失效 | agent loop 硬编码 `Stream: true`；现尊重该 flag 并自行打印非流式回复 |
| OpenRouter 归因头缺失 | `type: anthropic` 的 chat 路径与 online vision/OCR 路径未带 `HTTP-Referer` / `X-OpenRouter-Title`；现统一通过 `provider.SetAttribution` 补上 |
| wasm 解码 panic | 畸形 JPEG（截断、游离 EOI）会让 jpegli wasm 解码 trap 并 panic 整个进程；新增 panic-safe 的 `imgcodec.Decode/DecodeConfig`，预览路径不再崩溃 |
| 密钥文件权限 | 见上「安全」 |

## 其它

- Provider `Yunwu` 重命名为 `OpenLux`（yunwu.ai 已改名，API base 变为 `https://api.openlux.ai`，端点不变）。
- 测试覆盖率从 33.9% 提升到 40.6%（新增 15 个包的纯函数测试，未改生产代码）。
- 一批帮助文案/格式修正：`chat` / `video` 描述去掉单一后端限定，`mcp` 示例 server key 改为 `aigc-cli`，各本地命令 help 顶部补"首次使用先 `<cmd> init`"，`-v` 描述改为通用 debug。

## 验证

- `make fmt` / `make build` / `make lint`（0 issues）/ `make test`（47 个包全部通过）
- 实测：4 个本地命令的 `--json` 报 `unknown flag`；输入型 `--json` 正常；全局 `-o` 生效；`depth -o <dir>` 输出到指定目录

## 兼容性说明

本版包含若干**破坏性变更**：

- **移除输出 JSON**：`detect` / `ocr scan` / `ideas` / `background` 不再支持 `--json` 输出；机器可读结果请走 MCP。
- **`depth --output` 语义变更**：现在是全局输出**目录**，不再能自定义输出文件名；产物固定为 `<输出目录>/<文件名>_depth.png|.mp4`。
- **`background` / `depth` 的 `-o`**：局部短选项已并入全局 `--output`。
- **Provider `Yunwu` → `OpenLux`**：配置中使用 `yunwu` 的请改为 `openlux`（未保留旧名兼容别名）。
