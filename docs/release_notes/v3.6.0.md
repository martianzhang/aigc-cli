# Release Notes v3.6.0

> 本版最重要的改进：`config.yaml` 中的密钥现在会**自动加密落盘**（AES-256-GCM），主密钥由系统钥匙串托管、可用环境变量覆盖。此外图片生成失败会给出 `--size` 建议，`models` 单模型查询更稳，并新增 `--zdr` 零数据留存开关。

## Highlights

### 🔐 config.yaml 密钥自动加密

长久以来的诉求：配置文件里的 API Key 不再以明文躺在磁盘上。首次运行任意 `aigc-cli` 命令时：

1. 生成一把本地主密钥（age identity），存入系统钥匙串（macOS Keychain / Windows Credential Manager / Linux Secret Service）；
2. 扫描 `config.yaml`，把明文的 `api_key` / `api_secret`（含 `providers.*`、`web_search.*`）加密后写回。

```yaml
# 加密前
api_key: sk-xxx
# 加密后（enc:v1: 前缀）
api_key: enc:v1:8jjcyC8N4it1sd0ig-xLkmAY47HDqPuXZkWLOr-vuUNqx0Tkd8POFfdq5tl1
```

- **透明解密**：`config.Load` 遇到 `enc:v1:` 自动解密，其余代码无感；明文配置继续兼容。
- **加密方案**：主密钥经 HKDF-SHA256 派生（`config-v1` 域，与保险箱分离）出 AES-256-GCM 密钥，每次随机 nonce，格式 `enc:v1:<base64url(nonce||ciphertext)>`。
- **全入口覆盖**：常规命令、`config get/set/list`、`--print-config`、`mcp`、`kb` 都会触发；`config set api_key` 在写盘前就加密，绝不产生明文。
- **不写明文备份**：自动加密不生成 `.bak`（否则等于把密钥备份成明文）；`config set` 的备份是加密后的旧文件。
- **保留格式**：走 YAML 节点改写 + 原子替换，注释、键顺序、缩进保持不变。
- **并发安全**：首用生成用文件锁 `~/.config/aigc-cli/.master-key.lock` 串行化，避免两个进程各生成一把密钥导致数据打不开。
- **超时兜底**：钥匙串访问有 1s 超时，无头 Linux / 被锁定等场景不阻塞命令，只提示改用环境变量。

无头 / CI 环境用环境变量：

| 变量 | 作用 |
|---|---|
| `AIGC_CLI_MASTER_KEY` | 直接提供主密钥（`AGE-SECRET-KEY-…`），优先于钥匙串 |
| `AIGC_CLI_NO_KEYRING` | 设为非空则完全不访问钥匙串（也不生成） |

> ⚠️ 换机器或丢失钥匙串后，已加密的配置无法解密。CLI 会报错并提示设置 `AIGC_CLI_MASTER_KEY`（值为原密钥），否则需重新填写 API Key。

### 🖼️ image 失败时给出 `--size` 建议

不同厂商 / 模型接受的尺寸写法不同，写错通常返回 HTTP 400。现在 CLI 检测到「疑似尺寸问题」的失败时会自动追加该 Provider 的 `--size` 建议：

- **OpenRouter**：读 `GET /v1/images/models` 的 `supported_parameters`，列出该模型支持的 `aspect_ratio`（`--ratio`）与 `resolution`（`--size`）；模型不声明任何尺寸参数时提示删除 `--size` / `--ratio`。
- **其他 Provider**：给出文档化的写法速查（APIMart 的 `--resolution 1k/2k/4k`、Agnes 2.1 的 `2K@16:9`、ModelScope 纯像素等）。
- 只在**失败时**触发（成功路径零额外请求）；能力查询 best-effort，5s 超时后降级为静态建议。

### 🔎 `models` 单模型查询

`aigc-cli models <model>` 不再探测多数 Provider 不支持的 `GET /v1/models/{id}`（会 404），改为拉一次 `/v1/models` 列表后按 id 过滤；OpenRouter 走单数 `GET /v1/model/{author}/{slug}` 并原样输出 JSON（避免 array/map 解析崩溃）。

### 🕵️ `--zdr` 零数据留存

新增全局 `--zdr` 与配置项，OpenRouter chat-completions 请求会带上 `provider: {zdr: true, data_collection: "deny"}`：

```bash
aigc-cli chat --zdr --message "你好"
```

- 优先级：`--zdr` 参数 > `providers.{name}.zdr` > 全局 `zdr` > 关闭。
- 仅作用于 OpenRouter chat（含走 chat/completions 的 music）；image/video 与其他 Provider 为静默空操作，绝不注入不受支持的字段。

## 验证

- `make fmt` / `make build` / `make lint`（0 issues）/ `make test` 全部通过。
- 新增测试：主密钥（env 优先、超时、首用生成、文件锁并发 / 过期锁）、配置加解密（往返、幂等、错误密钥报错、无明文 `.bak`）、`--print-config` 自动加密。
- 实测：明文 config 经任意命令自动加密、二次运行不重复；错误主密钥解密报错退出（exit 1）；`config set api_key` 直接落密文。

## 兼容性说明

- **配置会被自动改写**：首次运行会把 `config.yaml` 中的明文密钥加密写回（注释、键顺序保留，不写明文 `.bak`）。这是有意的行为变更。
- **`kb init` 不再生成密钥**：主密钥改为首次运行任意命令时生成，`kb init` 只负责建库 / 下载模型；老的 vault identity 与配置加密复用同一把主密钥，保险箱无需迁移。
- **无新增配置字段**：加密值仍是字符串，带 `enc:v1:` 前缀；`http_proxy` 暂不加密（仅显示脱敏）。
