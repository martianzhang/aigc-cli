# Release Notes v3.3.0

> MCP 能力面全面扩大的功能版，同时完成发版前安全审计并修复全部存活发现。`aigc-cli chat` 的 TUI 调研已完成但按决定留档，本轮不实施。

## Highlights

### 🤖 MCP：29 工具 + 4 Prompts + 4 Resources + 注解 + 白名单

MCP 面从「工具列表」升级为完整的三件套（tools / prompts / resources），并补齐了此前 README 已宣传但未实现的 Midjourney：

| 能力 | 说明 |
|---|---|
| **Midjourney 工具** | 新增 `midjourney_imagine / describe / reroll / video`（此前 README 承诺「可在 MCP 中运行 Midjourney」但实现缺失） |
| **富媒体返回** | 生成类工具直接返回 image/audio content block，宿主（Claude Desktop 等）可在对话内联渲染；上限 4 文件 / 4 MiB，`AIGC_MCP_EMBED_MEDIA=0` 可关闭 |
| **Prompts** | 4 个工作流模板（`generate_product_shot` / `detect_ai_image` / `image_to_video` / `remove_image_background`），宿主渲染为可点击命令；`aigc-cli mcp --list-prompts` 可查 |
| **Resources** | `aigc://providers`（无密钥）、`aigc://config`（脱敏）、`aigc://output` 列表、`aigc://output/{file}` 模板——只读、防目录穿越、防符号链接、4 MiB 上限 |
| **provider 白名单** | `provider` 参数仅接受 `config.providers` 中已配置的名字，URL/路径形一律拒绝（生成类 8 个工具）；`generate_video` 因内部重解析而**诚实移除**该参数 |
| **Progress 通知** | video/music 生成时向宿主推送粗阶段进度（5% / 40%），无 progressToken 时零开销 |
| **Tool Annotations** | 29 工具 × 4 注解（readOnly / destructive / idempotent / openWorld）显式设置；回归测试守卫「全库无 destructive」 |
| **model 语义修正** | `model` 参数描述改为真实行为（image/video 默认配置优先，除非 `defaults.chat.allow_tool_override: true`） |

> **安全决策（延续 P0-4）**：MCP **不提供**任何写配置工具；不接受 `base_url` / `api_key` 入参；`web_fetch / grep / read_file / find` 仅限 chat，刻意不进 MCP（不可沙箱的文件/网络访问 = 注入风险）。

### ⚙️ `aigc-cli config set/get/list`

替代手编 YAML 的配置读写命令：

- 点号路径（`config get defaults.image.model`）
- **注释/顺序/类型保留**：基于 `yaml.v3` Node 往返，不重排用户文件
- 原子写 + `.bak` 备份；`api_key` / `base_url` / `providers.*` 写入需 `--force`
- `get` / `list` 永不全量回显密钥（与 `--print-config` 同一套脱敏）

> `--print-config` 保留：它显示「运行时实际生效值（含 CLI/env 覆盖 + 来源标注）」，`config list` 显示「文件里写了什么」，二者分工不同。

- **修复 bug**：`knowledgebase` 的 `map / prune / reset / search` 四个子命令因重复注册在 `--help` 中列出两次——已去重并有回归测试
- 全仓 **69 个帮助段 → 全部带示例**：root 新增 17 行工作流示例块（常见命令 + `--dry-run` / `--json` / `-v` 诊断三件套说明 + 文档/MCP 指引）；其余命令补 cobra `Example` 字段（示例全部可运行，已逐条验证）

### 🔒 发版前安全审计（3 猎人 + 2 PoC 工程师，双人独立验证）

对全仓（含新增 MCP/config 面）做了攻击面测绘 + auth/injection/secret + runtime/supply 三条线的审计，最强候选经 2 名 PoC 工程师**独立复现/证伪**，存活发现全部修复并有回归测试：

| 修复 | 发现 | 级别 |
|---|---|---|
| **Zip-Slip** | `audio init --url` 下载的 `.tar.bz2` 解压无路径约束，恶意归档条目可写出解压目录（任意文件写） | 🔴 高 |
| **MCP `output_path` 任意写** | watermark/background/depth 工具接受未约束的输出路径 + 符号链接穿透（可截断任意文件） | 🔴 中高 |
| **本地文件外传** | `generate_image` 的 `image_urls` 会把**任意本地文件**（含 id_rsa / config.yaml）base64 内联发送给 provider | 🔴 中高 |
| **`kb_fetch` SSRF + 代理绕过 + 无界读取** | 无内网 IP 守卫、绕过配置的 `http_proxy`、`ReadAll` 在尺寸检查前读满响应（实测 300MB→300MB RSS） | 🔴 中高 |
| **`kb_add` 任意文件读** | MCP 侧经 KB 读任意文本文件（绕过了「read_file 不进 MCP」的既定决策） | 🔴 高 |
| **KB 字面 `~` 路径** | MCP KB 指向 CWD 相对目录（默认不可用）且可被**预置知识库投毒**（持久 prompt injection） | 🟡 中 |
| **MCP server 缺失 `defaults:` 时 panic** | 审计中发现的可用性 bug | 🟡 中 |
| **图片解压炸弹** | 本地图片工具解码无尺寸上限（30000×30000 → 数 GB 分配） | 🟡 中 |
| **`generate_speech.format` 穿越** | format 无枚举约束 → 可构造写出 output 目录之外 | 🟢 低中 |
| **task_id 文件名穿越** | MCP `get_task` 下载文件名含未清洗的调用方 ID | 🟢 低 |

- **证伪**：onnxrt 的 zip/tgz 提取器经复核为安全（精确路径匹配 + `filepath.Base`）
- **留档（不修，记入 TODO）**：模型/原生库下载零完整性校验（需引入 sha256 发布体系）；`config .bak` 可预测 tmp（同用户攻击者前提）；MCP output 根默认 CWD（行为变更需产品决策）

## 兼容性说明

- **MCP KB 行为变更**：`kb_*` 工具此前因字面 `~` 路径 bug 默认不可用；现在指向 `~/.config/aigc-cli/knowledge`（与 CLI/chat 一致）——MCP 侧知识库功能从「坏了」变为「可用」，同时消除了投毒向量
- **`image_urls` 本地文件**：非图片文件（如 `~/.ssh/id_rsa`）不再被内联发送（`not a valid image file`）；>32 MiB 拒绝——这是收紧，理论上不应影响合法图片输入
- **MCP `output_path`**：显式输出路径被约束在 `cfg.Output` 与输入文件同目录两个根内，符号链接目标拒绝；默认「输出到输入旁」行为不变
- 其余 CLI 行为不变；`--print-config`、`config get/list`、`--dry-run` 的脱敏语义不变

> 版本号说明：MCP 能力面（Midjourney/富媒体/Prompts/Resources/白名单）、`config` 命令、`--help` 全面化、安全加固，均为向后兼容的功能新增/加固，故以 minor 号发布。
