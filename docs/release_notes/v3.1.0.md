# Release Notes v3.1.0

> Provider 路由一致性版本。核心是把散落在 CLI / chat(agent) / MCP 三个入口的 Provider 派发统一到共享策略表，并把 ZeekAI 从「手动开关」改为「按域名自动识别」。含**两处行为变更与一处配置字段移除**，见文末「兼容性说明」。

## Highlights

### 🔌 三个入口共用同一套 Provider 路由

同一命令在 CLI、chat agent 循环、MCP 工具三个入口此前各有一份派发逻辑，能力长期漂移：

| 命令 | CLI | chat agent 工具 | MCP 工具（v3.0.3） |
|---|---|---|---|
| `image` | 8 条策略全覆盖 | 仅 ZeekAI + APIMart，**其余静默降级**为 OpenAI 同步 | 缺 ModelScope / Gemini / Ollama |
| `video` | 4 条策略全覆盖 | 仅 OpenRouter + APIMart（缺 Agnes / Yunwu） | 缺 Yunwu |
| `music` | 3 条策略 | ✅ 已共用 | ✅ |

现在 `image` / `video` 的 `GenerateAndSave` 与 MCP 三个生成工具都走共享的 `imageStrategies` / `videoStrategies`，三个入口能力一致：

- **image**：OpenRouter / APIMart / Agnes / ModelScope / Gemini / Ollama / ZeekAI（`/images/edits`）/ 通用同步兜底
- **video**：OpenRouter / Agnes / Yunwu / APIMart
- **music**：OpenRouter / 阿里云百炼 Fun-Music / APIMart

MCP 侧因此删除 13 个逐 Provider 重复 helper（`tools_generate.go` 903 → 361 行），同时完整保留其专属能力（`gif` / `gif_width` / `crop_margin`）。

### 🖼️ ZeekAI 改为按域名自动识别

v3.0.3 引入的 `--image-edits json` 开关与 `providers.<name>.image_edits: json` 配置字段**已移除**。ZeekAI 现由 `zeekai.cc` 域名自动识别：图生图自动改走 `POST /images/edits`（`images[].image_url`，本地文件自动内嵌为 data URI），文生图仍走同步路径。

```bash
# 无需任何开关
aigc-cli image --provider zeekai --model gpt-image-2.5 -i photo.png -p "更换场景，保持人物"
```

## Bug Fixes

### `IsAPIMartProvider()` 绕过 Provider 解析

该函数直接读全局 `Shared.APIBase`，不参考已解析的 provider。当 `--provider` 指向非全局地址时判断错误：chat agent 的工具过滤（`midjourney_*` / `balance` / `task` 是否可用）与图生图的 sync/async 选择都会跟着错。

现改为接收已解析的 `*EffectiveProvider`；`--mode async|sync` 的覆盖语义保持不变。

### chat agent 生成工具使用错误凭据

`chat_exec_generate.go` 把 chat 自己的 client 传给了 image / video / music 生成函数。当 chat 与目标模态配置了不同 provider 时，请求会带着 **chat 的 base URL 与 API key** 发往目标模态端点，导致 401 或请求体不匹配。现三个工具各自解析目标模态 provider 并创建独立 client。

### MCP 视频漏 Yunwu、MCP 图片漏 ModelScope / Gemini / Ollama

MCP 的三处 `switch p.ProviderType` 与 CLI 策略表漂移所致。本次除补齐外，直接改为委派共享函数，从根上消除重复。

## Refactoring

- `image.GenerateAndSave` 改走 `imageStrategies`，并对齐 CLI 的两项前置处理：非 APIMart 剥离 `resolution`、APIMart 上传本地输入文件
- `video.GenerateAndSave` 改走 `videoStrategies`；因其 runner 各自创建 video 作用域 client，移除了已无用的 client 参数
- **MCP stdio 传输注入协议 writer**：`ServeStdio` 在**调用时**才读 `os.Stdout`，不能先重定向再调用它。故改为先捕获协议流、再把 `os.Stdout` 指向 stderr，用 `Listen(ctx, os.Stdin, protocolOut)` 注入。共享 runner 的进度输出因此不再可能污染 JSON-RPC 流；复用已有的 `options.SetStdout` 原语，**未改动任何 runner 的 150+ 处打印**
- 新增派发一致性测试：`TestImageStrategyDispatch_AllProviders`、`TestVideoStrategyDispatch_AllProviders`、`TestIsAPIMartProvider_ModeOverride`，以及 ZeekAI 检测与路由测试

## 兼容性说明

- ⚠️ **移除 `--image-edits` flag 与 `providers.*.image_edits` 配置字段**。ZeekAI 改为按 `zeekai.cc` 域名自动识别；**其他同样需要 `/images/edits` 的中转不再有开关可启用**（v3.0.3 提供的通用逃生通道被收窄）。如你依赖该开关对接非 ZeekAI 中转而不可迁移，请提 issue。
- 配置文件中残留的 `image_edits:` 键会被**静默忽略**（不报错）。
- **MCP 图片参数优先级变化**：现遵循 `defaults.image.*` 覆盖 Agent 传入的同名参数（与 CLI / chat 一致）；设置 `defaults.chat.allow_tool_override: true` 可恢复 Agent 优先。
- **MCP 生成响应文案简化**：不再返回 `Created:` / `Task ID:` / 费用行，改为仅列出已保存文件。

> 版本号说明：移除 `--image-edits` 与 `providers.*.image_edits` 属破坏性变更（该开关 v3.0.3 引入、v3.1.0 移除），故以 minor 号而非补丁号发布。若你依赖该开关对接非 ZeekAI 中转而不可迁移，请提 issue。
