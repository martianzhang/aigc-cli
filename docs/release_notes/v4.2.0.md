# Release Notes v4.2.0

> Chat 的联网原语按命名规则重构：**不带 `web_` = 内置免费实现；带 `web_` = 走第三方 API（可能计费）**。内置的本地抓取补齐 **SSRF 防护**；新增 **DeepSeek Search / Fetch** 能力。**含破坏性变更**：`web_fetch` 语义改变。

## Highlights

### 🧭 联网原语拆分：`search`/`fetch` vs `web_search`/`web_fetch`

Chat 现在有四个联网原语，命名即语义：

| 工具 | 含义 | 实现 | 成本 |
|---|---|---|---|
| `search` | 内置搜索 | DuckDuckGo 抓取 | 免费 |
| `fetch` | 内置抓取 | 本地 HTTP + readability | 免费 |
| `web_search` | 第三方搜索 API | 厂商由 `search_provider` 选择 | 按厂商 |
| `web_fetch` | 第三方抓取 API | **同一厂商**的抓取接口 | 按厂商 |

四个都是**特权原语**，需在 `tools_enable` 中显式开启。

- **不做单独的 `fetch_provider`**：厂商一般同时提供 search 与 fetch，因此 `web_search`/`web_fetch` **共用一个厂商选择**（`defaults.chat.search_provider` / `--search-provider`）。
- **只走第三方，不静默降级**：`web_search` 不再回落内置 DuckDuckGo；未配置任何第三方厂商时，`web_search`/`web_fetch` **明确报错并提示改用内置 `search`/`fetch`**——既不静默花钱，也不静默降级。
- `web_fetch` 需要**具备抓取能力的厂商**：`DeepSeek` 有；只有搜索能力的 `duckduckgo`/`brave` 没有。

### 🔎 新增 DeepSeek Search / Fetch

DeepSeek 自研搜索引擎，两个端点均为 `POST`、Bearer 鉴权、按成功请求计费（`$0.75 / 1000` ≈ `¥5 / 1000`，与返回条数无关）：

- Search：`POST https://api.deepseek.com/v1/tools/search`
- Fetch：`POST https://api.deepseek.com/v1/tools/fetch`（直接返回 Markdown）

配置（`api_key` 可与 `providers.deepseek` 共用）：

```yaml
web_search:
  deepseek:
    type: deepseek
defaults:
  chat:
    search_provider: deepseek   # web_search 与 web_fetch 共用
```

> 计费提醒：**本 CLI 直连该接口是立即计费的**；只有经由 DeepSeek Harness / Claude Code / Codex 的**服务端工具调用**在 2026-11-01 前免费。

### 🛡 内置抓取补齐 SSRF 防护

内置 `fetch`（原 `web_fetch`）此前直接用 `http.DefaultClient` 请求，缺少对私网地址的拦截。现在抽出共享叶子包 **`internal/netguard`**：

- `ValidatePublicURL`：拒绝回环 / 私网（RFC1918 / ULA）/ 链路本地 / 未指定 / 组播地址，以及解析到混合公网+私网地址的域名（防 DNS rebinding）；
- `NewGuardedClient`：拷贝 `http.DefaultClient`（保留全局代理与 transport），并挂上 `CheckRedirect`，**重定向逐跳复核**。

`kb fetch` 与 chat 内置 `fetch` 现在共用同一实现，消除了原先的重复代码。

## 实现要点

- `internal/search`：新增 `Fetcher` 能力接口（与 `Provider` 分离，`duckduckgo`/`brave` 仅实现 `Provider`）、`ResolveFetcher`（支持 `auto`/`free`/`quality`/厂商名，按名排序确定）、`RegisterRemote`（只注册第三方，不加 DuckDuckGo 兜底）。`DeepSeekProvider` 同时实现 `Provider` 与 `Fetcher`，Search/Fetch 共用一个带鉴权的 POST 收口函数。
- `internal/cli/chat`：新增 `executeBuiltinSearch` / `executeBuiltinFetch` / `executeWebSearch` / `executeWebFetch`；抽出 `renderFetch` 让内置与第三方共用同一套**字符分页**输出；新增 `resolveSearchVendor` 统一厂商解析。
- `internal/netguard`：由原 `internal/knowledge/fetch_guard.go` 抽出并导出，`knowledge` 与 `chat` 共用。

## 兼容性说明（⚡ 破坏性变更）

- **`web_fetch` 语义改变**：原 `web_fetch` = 免费本地抓取，现改为 **`fetch`**；新的 **`web_fetch` = 付费第三方抓取**。既有 `tools_enable: ["web_fetch"]` 会静默改变含义。
- **迁移**：
  - 想保留旧的免费本地抓取 → 改列 `"fetch"`（可再配 `"search"` 用内置搜索）；
  - 想用第三方 API → 保留 `"web_search"`/`"web_fetch"`，并在 `web_search.*` 配置厂商。
- **`web_search` 不再自动回落 DuckDuckGo**：未配置第三方厂商时会报错；需要免费搜索请用内置 `search`。
- **`kb search` 不受影响**：仍使用 `web_search.*` 厂商配置（含免费 DuckDuckGo 兜底），继续由 `defaults.knowledgebase.search_provider` 选择。
