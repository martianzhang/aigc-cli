# Release Notes v3.0.3

> 功能、修复与加固混合版本。新增能力均为**显式开关**（默认关闭），命令与参数保持向后兼容；少数失败路径的报错行为有变化，见文末「兼容性说明」。

## Highlights

### 🖼️ 图生图支持 `/images/edits` 型中转（`image_edits: json`）

部分 OpenAI 兼容中转（如 ZeekAI）在 `/images/generations` 上**不接受顶层 `image_urls`**，一律返回 `400 {"code":"invalid_request","message":"请求参数无效：请检查 prompt、model、n、size、quality、图片输入和回调参数"}`。此前 CLI 没有可用路径：`--edit` 硬性要求 APIMart provider，默认同步分支则始终把 `image_urls` 发往 `/images/generations`。

实测确认的接口契约（ZeekAI）：

| 请求 | 结果 |
|---|---|
| `/images/generations` + `image_urls`（含合法 data URI） | 400 拒绝 |
| `/images/edits` + multipart（`-F image=@file`） | 不支持 |
| `/images/edits` + `{"images":[{"image_url":"data:image/png;base64,..."}]}` | ✅ 通过校验并到达上游 |

用法（二选一）：

```bash
# 单次开启
aigc-cli image --provider zeekai --model gpt-image-2.5 --image-edits json \
  -i photo.png -p "更换场景，保持人物"

# 或在 config.yaml 的 provider 上固定开启
# providers:
#   zeekai:
#     base_url: "https://api.zeekai.cc"
#     image_edits: json
```

- 本地 `--image-url` 文件自动转为 `data:image/...;base64,...` 内嵌（复用 Agnes 那套 helper），无需公网 URL
- 该协议下 `--mask-url` 会**明确报错**，不静默丢弃参数
- 取值非法（如 `image_edits: multipart`）直接报错并列出支持值
- **默认关闭**：未开启时任何 provider 的请求与 v3.0.2 完全一致

### 🎵 `music` 新增阿里云百炼 Fun-Music 后端

`fun-music-v1` / `fun-music-preview` 是 DashScope 原生模型，既不走 OpenAI 兼容路径也不走 APIMart 异步路径：端点是 `POST /api/v1/services/audio/music/generation`（非 `compatible-mode/v1`），且所有可调参数嵌在 `input.*` 下。

- 新增 `Bailian` provider 类型，按 `*.maas.aliyuncs.com` / `dashscope.aliyuncs.com` 自动识别
- `FunMusicEndpoint` 只取配置 base URL 的 scheme+host 再拼原生路径，因此**一个命名 provider 同时服务 chat 与 music**，无需第二条配置
- `duration` / `title` 在 DashScope 无对应字段，会提示后忽略；`is_instrumental=true` 时按契约去掉 `lyrics` / `gender`
- 统一 `musicStrategies` 派发表，CLI / agent 循环 / MCP 工具共用同一入口；MCP `generate_music` 补上 Bailian 分支（否则会把 fun-music 模型发给 APIMart）
- 新增 `doJSONAbsolute`（原绝对 URL helper 仅支持 GET）

## Other New Features

### 缺少 API Key 时快速失败（`models` / `balance` / `task`）

这三个命令此前会带着**空密钥**发出请求，用户只拿到一个指向自己从未配置过的地址的 `401 invalid API key`。现在统一由共享守卫 `options.RequireAPIKey` 直接报错，并给出可操作信息：

```
Error: no API key for models (resolved base URL: https://api.apimart.ai)
fix: use --provider <name> or pass --api-key / set OPENAI_API_KEY (configured with keys: agnes, apimart, openrouter, ...)
```

- `models`：无参数（或查询单个模型）走 `/v1/models` 需要认证；`--type` / `--price` 免认证，不受影响
- `balance`：未指定 `--provider` 时仍遍历所有「已配置且带密钥」的 provider；显式指定的 provider 若缺密钥则直接报错
- `task`：`--provider` 现在真正生效（详见 Bug Fixes）

## Bug Fixes

### Agnes 图生图：本地图片未内嵌为 data URI（`400 extra_body.image is not a valid image base64`）

`image.go` 只在 `isAPIMart` 时才把本地文件解析为可用输入，Agnes 不是 APIMart，于是 `runAgnesImage` 把**裸文件名字符串**塞进了 `extra_body.image`；Agnes 没有上传端点、该字段只接受公网 URL 或 data URI，因此尝试 base64 解码一个文件名而失败。

- 本地文件改经 `service.LocalFilesToDataURI` 转为 data URI 后内嵌；请求变形抽为可测纯函数 `prepareAgnesImageRequest`
- **MCP `generate_image` 的同一份拷贝一并修复**（agent 循环同样受影响）

### `task` 忽略 `--provider`

`taskDeps()` 只注入 `shared.APIKey` / `shared.APIBase`，`--provider` 被静默丢弃，且 `task` 不在 `CmdProviderMap` 中，`defaults.task.provider` 也无法生效。结果 `task <id>` 与 `task --provider apimart <id>` 表现**完全相同**（空密钥打默认地址 → 401）。现改为与 `balance` / `models` 一致的 provider 解析，`--provider` 指定哪个账号/地址就查哪个。

### `--dry-run` 打印的 URL 不是真实请求地址

`buildImageCurl` 传入的是未归一化的 `p.BaseURL`，而 `client.NewWithProvider` 会给缺少版本号的 base 补 `/v1`：base_url 不带版本号的 provider，dry-run 打印 `https://host/images/generations`，真实请求却是 `https://host/v1/images/generations`。同时在 `image_edits: json` 下未反映 `/images/edits` 形状。

- 新增 `client.NormalizeBaseURL` 作为归一化唯一实现（`NewWithProvider` 与 dry-run 共用）
- dry-run 现在会按 `image_edits` 开关打印 `/images/edits` 请求体，并附一行注释说明本地文件会在发送前转成 data URI

### `audio`：非正采样率下的 panic / 除零

`Resample` 在 rate ≤ 0 时经 `int(+Inf)` 触发 `makeslice` panic，`MelFilterBank.Compute` 在 `sampleRate <= 0` 时除零。现返回空值、构造函数校验参数，并补表驱动回归测试。

### `--print-config` / MCP `get_config` 密钥脱敏收紧

见下方 Security 段。

## Refactoring

- 图片 data URI 转换提升为 `service.ImageToDataURI` / `service.LocalFilesToDataURI`，video / image / MCP 三处共用一份实现（原先仅 video 包内私有，其余两处各缺一份），MIME 改为先按字节嗅探再回退扩展名
- `client.NormalizeBaseURL`：base URL 版本归一化的唯一实现
- APIMart 默认 base URL 统一为 `types.DefaultAPIBaseURL`，替换 4 处重复常量与 6 处字面量，避免内置默认值漂移；同时删除 `options.ResolveProvider` 中已可证明为死代码的 `ep.BaseURL` 兜底并用测试锁定该契约
- image：抽出 `saveOpenAIImageResponse`，同步与 `/images/edits` 两个 runner 共用

## Security

### `--print-config` / MCP `get_config` 密钥脱敏统一收紧

两条配置输出路径此前各自维护一份脱敏逻辑，且**保留前 8 位**（如 `sk-9V3z0...`），密钥越短暴露越多；`base_url` / `http_proxy` 更是原样输出，URL 中内嵌的密钥会完整泄漏。

修复：

- 新增 `service.MaskConfigSecrets`：深拷贝后统一脱敏全局 `api_key`、每个 `providers.*` 的 `api_key`/`base_url`/`http_proxy`、每个 `web_search.*` 的 `api_key`
- 新增 `service.RedactURLSecrets`：脱敏 URL 中的 `user:pass@`、`key/token/secret/password/...` 查询参数，以及形如 `sk-xxx` 的路径段（替换为 `REDACTED`）
- API Key 仅保留后 4 位（与 v3.0.1 的 `--dry-run` 标准一致）；未设置的字段保持省略，不再出现无意义的 `***`
- `--print-config` 不再原地修改进程内的 `shared.Cfg`，改为深拷贝后展示
- MCP `get_config` 工具改用同一套实现

## Changes

### 移除 `--print-config` 末尾的「各命令有效 Provider」概览

该概览只调用 `ResolveProvider`，未复用各命令真实的在线/离线分支判断，导致**结论错误**：`audio` / `detect` / `background` 未配置 provider 时实际走本地（sherpa-onnx / ONNX），概览却显示为 `(global) (APIMart)`。同时它对该段落上方 YAML 已展示的信息是冗余的，且 `model` 列对 `audio` / `midjourney` 恒为空。

现在 `--print-config` 以 YAML 配置块为唯一准确来源（`defaults.{命令}.provider` + `providers` 段）。

## 兼容性说明

- 新增能力（`image_edits`、百炼 music）**默认关闭 / 自动识别**，命令、参数、配置文件向后兼容
- 失败路径变化：`models` / `balance` / `task` 缺少 API Key 时由「发出空密钥请求 → 远端 401」变为「本地直接报错并提示，退出码 1」
- `--dry-run` 输出变化：`base_url` 不含版本号的 provider，打印的 URL 变为真实请求地址（原先打印的是一个从未被调用的地址）
- 图片响应中 0 张图时现在返回错误（原先静默 `exit 0` 无输出）
