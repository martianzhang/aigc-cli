# Release Notes v4.1.0

> 新增 `--inject-json`：在 CLI 生成的请求体上**叠加一段 JSON**，用于传入联网搜索、推理强度、路由偏好等 CLI 未建模的厂商私有关键字段。覆盖 `chat` / `image` / `video` / `music` / `midjourney`。同时修复了 agent loop / TUI 每轮重建请求时丢失注入字段的 bug。**无破坏性变更**。

## Highlights

### 🧩 新增 `--inject-json`（与 `--json` 平级）

`--inject-json` 是第二套 body 输入通道：把你给的一小段 JSON **合并进** CLI 生成的最终 body。

- **合并语义**：对象递归合并；**数组拼接**（CLI 的在前，你的在后）；标量/其它值覆盖。
- **优先级**：typed 字段 / CLI 参数 < `--json` < `--inject-json`——`--inject-json` 永远最后生效。
- **输入**：文件路径、内联 JSON 或 `-`（stdin）；值必须是 JSON **对象**，否则命令直接报错。
- **覆盖命令**：`chat` / `image` / `video` / `music` / `midjourney`。
- **不接入**：`decision`（其 `--json` 是题库、不是 API body）与 **MCP**（保持工具参数白名单边界，不接受任意 body 注入）。

例：OpenRouter 联网搜索（插件是 chat-completions 的 body 字段）：

```bash
aigc-cli chat -P openrouter --model anthropic/claude-sonnet-5.5 \
  --message "明天纽约天气" --no-stream \
  --inject-json '{"plugins":[{"id":"web","max_results":5}]}'
```

例：Anthropic 原生联网搜索：

```bash
aigc-cli chat --message "最新的 Go 版本" \
  --inject-json '{"tools":[{"type":"web_search_20250305","name":"web_search"}]}'
```

> `--inject-json` 的内容是 **provider 相关**的，CLI 不做转换：`{"enable_search":true}` 只对百炼 OpenAI 兼容协议有效；Anthropic 原生用 `tools:[{"type":"web_search_20250305",...}]`；OpenAI Responses 用 `tools:[{"type":"web_search_preview"}]`；OpenRouter 用 `plugins:[{"id":"web"}]`（或模型名后缀 `:online`）。写不准时先 `--dry-run` 看待发 curl。

### 🐛 修复：agent loop / TUI 丢失 `--inject-json`

`chat` 的 agent loop 与交互式 TUI **每一轮都会重建 `ChatRequest`**，重建时没有带上 `InjectJSON`，导致 `--inject-json` 只在单轮 / `--dry-run` 路径生效，真实 `--message` 与交互模式里被静默丢弃（OpenRouter `plugins`、服务端 `web_search` 等注入因此失效）。

现已修复：`buildChatRequest` 解析一次并缓存，agent loop 与 TUI 每轮请求都重新应用注入；新增回归测试 `TestRunAgentLoopAppliesInjectJSON`。

## 实现要点

- 新增叶子包 `internal/jsonmerge`（零依赖，避免 `types` ↔ `service` 循环）提供加法式合并。
- 各请求类型新增 `InjectJSON`，在 `MarshalJSON` / `BodyOrRaw` 等收口处统一叠加；`client` 层 `AnthropicChatBody` / `ResponsesBody` 及会绕过 `MarshalJSON` 的路径（APIMart/Gemini 预览、ModelScope/Ollama/FunMusic map、multipart 表单、OpenRouter 模型变体）均覆盖。
- `BodyOrRaw` / `RawOr` 改为返回 `(any, error)`，不再吞掉注入错误。

## 验证

- `make fmt` / `make build` / `make lint`（0 issues）/ `make test` 全部通过（52 个包）。
- 新增测试：`internal/jsonmerge` 表驱动（对象递归 / 数组拼接 / 标量覆盖 / 数字精度 / 非法输入）；`types` 注入三类场景；`client` 的 Anthropic / Responses / BodyOrRaw 注入；`service.ReadInjectJSON`；`chat` 的 agent-loop 注入回归。
- 各命令 `--dry-run` 实测注入键均出现在最终 body。

## 兼容性说明

- **无破坏性变更**。
- **已知限制**：数组只能追加、无法清空或替换；值必须是对象，不接受数组或标量。
- `--inject-json` 的内容是 provider 与端点相关的（例如 `plugins` 属 chat-completions，塞进 Anthropic `/messages` 会被忽略）；CLI 不做转换。
