# Release Notes v4.3.0

> 新增顶层 `aigc-cli search` 与 `aigc-cli fetch`，把联网搜索 / 网页抓取从 chat/MCP 内部能力提升为独立 CLI 命令；搜索厂商配置统一到 `defaults.search.provider`。同时**移除** `auto/free/quality` 策略、quota、`tags/weight/period` 以及轮询/fallback。**含破坏性配置变更**（见文末）。

## Highlights

### 🔍 `aigc-cli search`：直接输出厂商原始 JSON

```bash
aigc-cli search "golang context timeout"
aigc-cli search "vector database" -P deepseek -n 10
aigc-cli search --json '{"query":"golang context","provider":"exa","limit":3}'
aigc-cli search "golang" --inject-json '{"type":"neural"}'
aigc-cli search --list-providers
```

- 不做 title/url 归一化，直接输出实际执行厂商的响应体（snippets、score、metadata 都保留）
- `--provider / -P` 显式选择厂商；未指定时用 `defaults.search.provider`，再回退 `duckduckgo`
- `--json` 命令级输入（文件或 inline）；stdin 专用于 query，支持 `echo "..." | aigc-cli search`
- `--inject-json` 注入厂商原生字段：POST 合入 body，GET 转 query 参数
- `--dry-run` 打印选中厂商的等价 curl（API key / cookie 值掩码）
- `--list-providers` 查看厂商、search/fetch 能力、可用状态与不可用原因
- `--provider` 支持 shell 动态补全

### 🌐 `aigc-cli fetch`：URL / 本地文件 → Markdown

```bash
aigc-cli fetch https://go.dev/doc/effective_go
aigc-cli fetch https://go.dev/doc/effective_go > effective_go.md
aigc-cli fetch ./page.html > page.md
aigc-cli fetch https://example.com/private -H "Authorization: Bearer $TOKEN"
aigc-cli fetch https://example.com/private -b cookies.txt -c cookies.txt
aigc-cli fetch https://example.com/article --html > page.html
aigc-cli fetch https://example.com/article --dry-run
```

- 默认内置免费抓取：HTML → readability 正文 → Markdown；JSON/plain text 原样输出；二进制报错
- 参数先做本地文件存在性检测，本地 HTML/文本不联网直接转换
- 第三方抓取：`-P deepseek` / `-P exa`；厂商不支持 fetch 时回退内置抓取并提示
- curl 兼容：`-H/--header`、`-b/--cookie`（inline 或 Netscape 文件）、`-c/--cookie-jar`（Set-Cookie 回写、0600 原子写）
- `--html` 输出原始 HTML / 原始文本；`--max-chars` 按 rune 截断
- `--dry-run` 输出等价 curl；`-v` 输出标题、最终 URL、类型、大小
- 所有请求走全局 `http_proxy` / `HTTP(S)_PROXY`

### 🧱 共享抓取核心 + 提取质量改进

- 新增 `internal/webfetch`，`fetch` / chat `fetch` / `kb fetch` / `knowledge.FetchURL` 共用同一套 HTTP + charset + readability + Markdown 管线
- 默认使用浏览器 User-Agent，减少站点返回 JS 跳转/反爬空页
- readability 只抓到页脚时回退整页转换，并移除 script/style/footer，保留导航
- 清理 Markdown 中的 `data:` URI（base64 图片）和 `javascript:` 链接
- 正文为空时明确报错，不再输出空白

### 🧭 Provider 注册表 UX

- 配置了但构造失败的 provider 会提示 `configured but unavailable: <原因>`，不再静默消失
- `search --list-providers` / `fetch --list-providers`
- `--provider` help 不再硬编码厂商列表
- `--provider` 动态 shell 补全（`search` 全部，`fetch` 仅 fetch-capable）

## ⚠️ 破坏性变更（升级前必读）

### 1. 搜索厂商配置统一到 `defaults.search.provider`

旧键已删除，不再兼容：

```yaml
# 旧
search_provider: deepseek
defaults:
  chat:
    search_provider: deepseek
  knowledgebase:
    search_provider: deepseek
```

改为：

```yaml
defaults:
  search:
    provider: deepseek
```

所有入口（`aigc-cli search`、`kb search`、chat/MCP `web_search`/`web_fetch`、MCP `kb_search`）共用该默认值。

### 2. 移除 `auto` / `free` / `quality` 策略

- `--provider` 只接受具体厂商名
- `search` / `kb search` 未配置时默认 `duckduckgo`
- chat / MCP `web_search` / `web_fetch` 未配置时报错，不静默使用内置引擎
- `-P auto` / `-P free` / `-P quality` 现在会报“未配置厂商”

### 3. 移除 quota / tags / weight / period 与轮询

`web_search.*` 只保留 `type` 和 `api_key`：

```yaml
web_search:
  deepseek:
    type: deepseek
    api_key: "sk-xxx"
```

- 不再有配额、weight 加权、随机轮询或跨厂商 fallback
- 每次只调用一个厂商；失败直接报错（`fetch` 的 search-only 厂商仍回退内置抓取）

## 升级建议

1. 把旧 `search_provider` / `defaults.chat.search_provider` / `defaults.knowledgebase.search_provider` 合并到 `defaults.search.provider`
2. 删除 `web_search.*` 下的 `tags` / `quota` / `period` / `weight`
3. 把脚本里的 `-P auto/free/quality` 改为具体厂商名
4. 运行 `aigc-cli search --list-providers` 确认配置生效
5. 需要抓取登录页面时使用 `-H` / `-b` / `-c`；需要原始 HTML 时加 `--html`
