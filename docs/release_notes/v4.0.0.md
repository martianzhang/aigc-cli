# Release Notes v4.0.0

> **重大版本**。本版彻底重构 Chat 的**工具层**：借鉴 pi coding agent，Chat 只保留少量**基础原语**（`read` / `write` / `edit` / `bash` / `grep` / `find` / `ls` / `web_fetch`），生成 / 检测 / 知识库等**领域工具全部改由 MCP 服务器提供**。Chat 现在可作为一个 **MCP 客户端**接入任意 stdio MCP 服务器（包括 `aigc-cli mcp` 自身），**不再在 Chat 内重复定义工具**。附带工具**按需加载**、可配置的 `read` 访问策略，以及若干体验修复。

## ⚠️ 破坏性变更（升级前必读）

1. **Chat 工具面重构**：Chat 不再内置领域工具。要像以前一样在 Chat 里生成图片 / 检测 / 用知识库，**必须配置 `mcp.servers` 指向 `aigc-cli mcp`**：

   ```yaml
   mcp:
     servers:
       - name: aigc
         command: aigc-cli      # 不在 PATH 时用绝对路径
         args: ["mcp"]
   ```

   不配置时，Chat 只有原语（文件读写 + shell + 网页抓取），没有生成 / 检测 / KB 工具。

2. **工具改名 / 迁移**：
   - `read_file` → **`read`**（参数不变：`filepath` / `offset` / `limit`）。
   - Chat 的 `balance` / `task` 移除，改用 MCP 的 **`get_balance` / `get_task`**。
   - 其余领域工具（`generate_*`、`midjourney_*`、`recognize_text`、`kb_*` …）由 MCP 提供，**名称保持不变**。

3. **`tools_enable` 语义细化**：
   - **只读原语** `read` / `grep` / `find` / `ls` **默认可用**；
   - **特权原语** `write` / `edit` / `bash` / `web_fetch` **默认关闭**，必须在顶层 `tools_enable` 中显式列出才启用（把 shell / 写文件交给模型的安全闸门）；
   - 领域工具（MCP 来源）在有 `tools_enable` 时按白名单过滤，为空则全部允许；`tools_disable` 永远优先。

4. **`read` 默认放行任意文件**：移除了原先硬编码的扩展名白名单（它曾导致 `go.mod` / `Makefile` 等被误拒）。如需限制，请用正则黑名单：

   ```yaml
   defaults:
     chat:
       read_deny: ['\.pem$', '^id_rsa$', '\.env$']   # 匹配路径或文件名；空 = 全部放行
   ```

## Highlights

### 🧩 Chat 工具原语化 + MCP 客户端

- Chat 内置工具仅剩少量**原语**（命名对齐 pi）：`read` / `write` / `edit` / `bash` / `grep` / `find` / `ls` / `web_fetch`。
- 新增 **MCP 客户端**：`mcp.servers[]`（`name` / `command` / `args` / `env` / `tools_enable` / `tools_disable` / `enabled`），通过 stdio 连接任意 MCP 服务器，把其工具并入 Agent，执行走标准 `tools/call`。
- **无内置服务器**：`aigc-cli` 自身也作为一个普通 server 条目接入，配置统一、天然支持第三方 MCP。
- 领域工具定义与执行适配**只保留一份**（在 MCP 侧），删除了 Chat 内重复的 `chat_exec_*` 实现。

### 🪄 工具按需加载

工具很多、上下文吃紧时，可开启：

```yaml
defaults:
  chat:
    tools_on_demand: true
```

开启后请求只带原语 + 两个元工具：模型先 `search_tools`（关键词 → 工具名 + 简介）找到所需工具，再 `load_tools` 加载，其完整 schema 才在**后续轮次**进入上下文。原语始终可用。

### 🖥️ `!command` 回显命令本身

交互模式下执行 `!<命令>`，结果区现在会先回显 `$ <命令>` 再附输出，便于确认到底执行了什么。

### 🔧 结果形状

- MCP 工具返回的图片 / 音频**不内联进对话**（多模态回流不做）；工具结果以**文本**呈现，生成的媒体已在文本里带**本地文件路径**（如 `已保存的图片: <path>`）——模型据此告知用户文件位置。仅媒体、无文本的结果会以 `[media result without a local file path]` 兜底。

## 升级步骤

1. 升级二进制。
2. 在 `~/.config/aigc-cli/config.yaml` 配置 `mcp.servers`（见上）。
3. 如需 Chat 执行 shell / 写文件，在 `tools_enable` 中显式加入 `bash` / `write` / `edit` / `web_fetch`。
4. 若原依赖 `read_file` 名称或 Chat 的 `balance` / `task`，改用 `read` / `get_balance` / `get_task`。
5. 若希望限制 `read`，配置 `defaults.chat.read_deny`。

## 验证

- `aigc-cli chat --message "用 read 工具读一下 go.mod 的前 5 行"` —— 应成功（不再报 `security reasons`）。
- `aigc-cli chat --message "用 get_config 工具查看当前配置"` —— 经 MCP 往返（需已配置 `mcp.servers`）。
- 未启用 `bash` 时，要求模型执行 shell 命令 —— 模型应表示没有该工具。
- 开启 `tools_on_demand` 后 `/tools` 应显示原语 + `search_tools` / `load_tools`。
