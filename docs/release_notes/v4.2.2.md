# Release Notes v4.2.2

> MCP 补齐**联网工具**：新增 `search` / `fetch` / `web_search` / `web_fetch`（30 → 34 个工具），`kb_search` 不再写死 DuckDuckGo，并新增顶层 `search_provider` 作为全局默认厂商。同时 `--list-tools` 可以看到**全部**工具及其被禁用的原因。**含 3 处行为变更**（见文末）。

## Highlights

### 🌐 MCP 联网能力：统一命名 + 真正可配厂商

此前 MCP **完全没有**「纯检索/抓取」工具——只有「搜完入库」的 `kb_*`；而且 `kb_search` 源码里写死 DuckDuckGo，`firecrawl`/`brave`/`doubao`/`deepseek` **在 MCP 里根本不生效**。

现在 chat 与 MCP 共用同一条命名规则：

| 工具 | 语义 | 计费 |
|---|---|---|
| `search` / `fetch` | 内置实现（DuckDuckGo 抓取 / 本地 HTTP + readability） | 免费，无需 API Key |
| `web_search` / `web_fetch` | 第三方厂商 API | 按厂商计费 |

厂商选择收敛到一个**全局默认** `search_provider`，各 scope 可覆盖：

```yaml
search_provider: deepseek      # 全局默认（新增）
web_search:
  deepseek:
    type: deepseek             # 同时具备 search 与 fetch
  brave:
    type: brave                # 仅搜索，不能用于 web_fetch
defaults:
  chat:
    search_provider: brave     # 只影响 chat
```

| 入口 | 选择键 |
|---|---|
| MCP `web_search` / `web_fetch` | 顶层 `search_provider` |
| chat `web_search` / `web_fetch` | `--search-provider` > `defaults.chat.search_provider` > `search_provider` > `auto` |
| MCP `kb_search` / `kb search` | `defaults.knowledgebase.search_provider`（含免费 DuckDuckGo 兜底） |

`search_provider` 取值：`auto`（默认）| `free` | `quality` | 厂商名。

**不静默降级**：`web_search`/`web_fetch` 未配第三方厂商时**明确报错**并指向内置 `search`/`fetch`，既不静默花钱也不静默降级。

### 🧩 `internal/webtool`：搜索/抓取成为共享层

原先同一件事有 4 份实现（chat 原语、MCP `kb_*`、`kb` 子命令、散落的 DDG 包装）。现在抽出 **`internal/webtool`**，它**不读配置**——vendor spec 与 provider 注册表由调用方传入，因此 chat（flag + chat scope）与 MCP（全局 scope）各解各的 scope，共用同一套执行逻辑。chat 的四个原语退化为薄包装，行为不变。

### 🛡 同名工具去重 + 内置原语优先

给 MCP 加同名工具会踩两个雷，本次一并修掉：

1. **重复 function 名** —— `toolRuntime.RequestTools()` 原先直接拼接内置与 MCP 工具，不去重；同名工具会让请求里出现两个同名 function，多数厂商直接报错。现在**按名去重**。
2. **静默替换** —— `executeToolCallMCP` 原先 MCP 优先，意味着 MCP server 能悄悄顶掉 `read`/`bash` 这类敏感原语。现在**内置原语优先**，被屏蔽的 MCP 工具在 `-v` 下会打印出来。

### 📋 `--list-tools` 能看到全部工具

```bash
aigc-cli mcp --list-tools            # 全部 34 个，逐行标注状态与原因
aigc-cli mcp --list-tools=all        # 同上，显式写法
aigc-cli mcp --list-tools=enabled    # 只看真正会暴露的
```

```
MCP tools: 34 registered, 28 enabled

  ✅ generate_image            Generate images via AI
  ⛔ get_balance               Query API key or account balance  [in tools_disable]
  ⛔ generate_speech           Convert text to speech (TTS)  [not in tools_enable]

  tools_disable: [get_balance]
```

方括号里说明是**哪条规则**拦下的。flag 由 `Bool` 改为 `String` + `NoOptDefVal="all"`，裸 `--list-tools` 行为不变；顺带堵了两个坑：`--list-tools=`（空值）不再静默启动 stdio server，非法模式明确报错。

## 实现要点

- **`internal/webtool`**（新增）：`Search`/`Fetch`（内置）与 `WebSearch`/`WebFetch`（第三方）+ `Env{Spec, Providers, Scope}`；`RenderFetch`、`TakeChars`、`FormatSearchResults` 一并抽出。
- **`internal/mcp`**：新增 `tools_web.go`（4 个工具定义 + handler + `webEnv()`）；`kb_search` 改走 `search.RegisterAll` + `ResolveStrategy`；`Config` 新增 `SearchProvider` / `KBSearchProvider` / `WebSearchProviders`。
- **`internal/types`**：顶层 `Config.SearchProvider`（`search_provider`）。
- **`internal/cli/chat`**：`search.go`/`chat_query.go` 改为 webtool 薄包装；`resolveSearchVendor` 增加全局回落；`tool_runtime.go` 去重；`chat_exec.go` 内置原语优先。
- **删除死代码**：`internal/agent/tool_kb.go` / `tool_kb_read.go` / `tool_kb_write.go`（v4.2.0 把领域工具迁到 MCP 后已无任何调用点）。

## 行为变更（⚡ 3 项）

| 变更 | 说明 | 需要做什么 |
|---|---|---|
| **新增 4 个 MCP 工具** | 30 → 34：`search` / `fetch` / `web_search` / `web_fetch` | 用 `tools_enable` 白名单时，需显式加入想开放的工具 |
| **`kb_search` 不再写死 DuckDuckGo** | 改用搜索路由，`firecrawl`/`brave`/`doubao`/`deepseek` 现在对 MCP 生效（保留免费 DDG 兜底）；结果条数上限 5 | 无需操作；此前「配了厂商却不生效」的问题已修复 |
| **内置原语优先于同名 MCP 工具** | chat 中若 MCP server 也提供 `search`/`fetch`/`read`/… 同名工具，CLI 自己的实现优先，同名 MCP 工具不再下发也不再执行 | 若你依赖某个 MCP server 覆盖内置 `read`/`bash`，请给该 MCP 工具改名 |
