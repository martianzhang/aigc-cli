# v2.1.2 — 无全局 API Key 时自动使用命名 Provider 的 Key

## Bug 修复

### 全局 API Key 检查误拦截

当用户将 `api_key` 移入命名 Provider（如 `providers.apimart.api_key`）且全局 `api_key` 为空时，`PersistentPreRunE` 的 API Key 检查错误地拒绝执行，即使命令的默认 Provider 有自己的 Key。

**修复：** 在检查全局 API Key 之前，先查当前命令的 `defaults.{cmd}.provider` 是否指向一个有 `api_key` 的命名 Provider。如果是，跳过全局检查。
