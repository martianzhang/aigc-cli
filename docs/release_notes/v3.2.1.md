# Release Notes v3.2.1

> `--json` 逐字透传的补丁版本。v3.2.0 承诺「原文字节**原样**成为请求体，对所有 provider 生效」，但 OpenRouter / Gemini / Ollama / ZeekAI 图生图四条路径会重建请求体、静默丢弃未建模字段，`--dry-run` / `--verbose` 也随之失真。本版补齐这四条路径，并让诊断输出说真话。

## Highlights

### 📨 `--json` 逐字透传现在真正覆盖全部 provider

v3.2.0 起 `--json` 的原文会原样成为请求体，但以下四条路径此前会重建请求体，丢弃 `loras` / `seed` / `steps` / 厂商私有字段：

| Provider | 真实端点 | 此前的错误行为 |
|---|---|---|
| OpenRouter | `POST {base}/images` | 重建 `bodyMap`，原文被丢 |
| Gemini | `POST {base}/interactions` | 重建 `input` / `response_format`，原文被丢 |
| Ollama | `POST {ollama 原生 base}/api/generate` | 只发 `model` / `prompt` / `stream` |
| ZeekAI 图生图 | `POST {base}/images/edits` | 重建 `images[].image_url`，原文被丢 |

现在这四条路径在 `--json` 下都直接发送用户原文；`--flag` 路径仍走各 provider 的字段映射，行为不变。

### 🧪 `--dry-run` / `--verbose` 不再说谎

此前两者恒以 `json.Marshal(req)` 渲染到 `/images/generations`：既打印了随后会被丢弃的字段，又打印了**错误的端点**（OpenRouter 真实是 `/images`、Gemini 是 `/interactions`、Ollama 是 `/api/generate`）。现在它们复用与真实请求**同一套组包函数**，按 provider 输出真实端点与真实请求体，可以直接用来验证厂商新参数是否已接通。

```bash
aigc-cli image --provider openrouter --json '{"model":"m","prompt":"p","loras":"u/r"}' --dry-run
# curl -X POST https://openrouter.ai/api/v1/images \      ← 真实端点
#   -d '{"model":"m","prompt":"p","loras":"u/r"}'          ← 逐字原文
```

## 兼容性说明

- **v3.2.0 的措辞过宽**：当时写「对所有 provider 生效」，实际只有 OpenAI 兼容同步 / APIMart / ModelScope / Agnes 成立。本版补齐后该措辞才成立（文档已同步收紧并附端点表）。
- 逐字透传要求写**该 provider 的原生形状**（OpenRouter 用 `input_references`、Gemini 用 `input` / `response_format`、Ollama 用 `/api/generate` 形状）；CLI 不做转换。

## Internal

- `types.GenerateRequest` 新增 `BodyOrRaw(built)`：`RawJSON` 非空时返回原文，否则返回调用方构建的 body
- 抽出 `client.OpenRouterImageBody` / `client.GeminiImageBody` / `service.OllamaGenerateBody` / `service.OllamaGenerateURL`，真实请求与 dry-run / verbose 共用，消除导致静默分叉的重复
- 端点常量化并导出（`client.ImageSubmitPath` / `ImageEditsPath` / `OpenRouterImagesPath` / `GeminiInteractionsPath`），避免真实请求与预览再次漂移
- `buildImageCurl` 改为接收已解析的 provider，按类型选择端点与请求体

## 验证

- `make fmt` / `make build` / `make test`（42 包全绿）/ `make lint`（0 issues）
- 新增**离线**测试（`httptest`，零网络、零付费）：四条路径的 `RawJSON` 逐字到达真实端点；flag 路径仍为原 body；`--dry-run` 按 provider 指向正确端点
- 实测 `--dry-run`：openrouter → `/v1/images`、gemini → `/v1/interactions`、ollama → `/api/generate`、zeekai 图生图 → `/v1/images/edits`，原文逐字保留
