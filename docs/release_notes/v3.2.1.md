# Release Notes v3.2.1

> `--json` 逐字透传的补丁版本。v3.2.0 承诺「原文字节**原样**成为请求体，对所有 provider 生效」，但只有 `image` 的一部分路径真正做到了：其余命令仍把 `--json` 解析进类型化结构体，静默丢弃未建模字段；`--dry-run` / `--verbose` 也随之失真。本版把逐字透传补齐到 `image` / `video` / `midjourney` / `chat` 四条命令，并让诊断输出说真话。

## Highlights

### 📨 `--json` 逐字透传现在真正覆盖四条命令

v3.2.0 起 `image` 的 `--json` 原文会原样成为请求体，但以下路径此前会重建请求体、丢弃未建模字段（`loras` / `seed` / `steps` / 厂商私有键）：

| 命令 | 此前的错误行为 |
|---|---|
| `image`：OpenRouter / Gemini / Ollama / ZeekAI 图生图 | 重建 body，原文被丢 |
| `video` | 解析进 `VideoGenerateRequest`，未知字段丢弃，且 CLI 用 `size`/`resolution` 默认值**覆盖**用户意图 |
| `midjourney`（10 个子命令） | 解析进 `MJ*Request`，未知字段丢弃，并注入 `speed`/`version` 默认值 |
| `chat` | 解析进 `ChatRequest`，`reasoning_effort` / `response_format` / `top_k` 等全部传不了 |

现在四条命令在 `--json` 下都直接发送用户原文；`--flag` 路径行为不变（仍按 provider 映射字段并补默认值）。`music` 从 v3.2.0 起就用「`Extras` 末尾合并」实现了同样的能力，未改动。

### 🧪 `--dry-run` / `--verbose` 不再说谎

此前它们恒以 `json.Marshal(req)` 渲染，并用**全局 `APIBase`**（而非解析出的 provider）拼 URL，于是：

| 命令 | 修复前 | 修复后 |
|---|---|---|
| `image` | 恒为 `/images/generations` | OpenRouter `/images`、Gemini `/interactions`、Ollama `/api/generate`、ZeekAI 图生图 `/images/edits` |
| `video` | 恒为默认 apimart host + `/videos/generations` | OpenRouter/Agnes `/videos`、Yunwu `/video/create`、Pollinations GET、APIMart `/videos/generations` |
| `midjourney` | host 恒为默认 apimart（忽略 `--provider`） | 解析出的 provider host |
| `chat` | **没有 `--dry-run`** | 新增；`/chat/completions`（或 Anthropic `/messages` + `x-api-key`） |

现在 `--dry-run` 与 `--verbose` 复用与真实请求**同一套组包函数**，可用来验证厂商新参数是否已接通。

## 兼容性说明

- **v3.2.0 的措辞过宽**：当时写「对所有 provider 生效」，实际只有 OpenAI 兼容同步 / APIMart / ModelScope / Agnes 成立。本版补齐后该措辞才成立（`docs/{zh,en}/guide-image.md` 已同步收紧并附端点表）。
- 逐字透传要求写**该 provider 的原生形状**（OpenRouter `input_references`、Gemini `input`/`response_format`、Ollama `/api/generate`、ZeekAI 图生图 `images[].image_url`）；CLI 不做转换。
- `chat --json` 不再强制注入 `"stream": true`：原文写什么就是什么。
- `--flag` 路径（`--model` / `--prompt` / `--image-url` / `--message` 等）行为不变。

## Internal

- `types.GenerateRequest` 新增 `BodyOrRaw`；`VideoGenerateRequest` / `ChatRequest` / 10 个 `MJ*Request` / `OpenRouterVideoRequest` 新增 `RawJSON` + `MarshalJSON`，统一经 `marshalVerbatim` / `RawOr` 出口
- 抽出 `client.OpenRouterImageBody` / `client.GeminiImageBody` / `client.AgnesVideoBody` / `client.YunwuVideoBody` / `client.AnthropicChatBody` / `service.OllamaGenerateBody` 等共享组包函数，真实请求与预览共用，消除导致静默分叉的重复
- 端点常量化并导出（`client.ImageSubmitPath` / `ImageEditsPath` / `OpenRouterImagesPath` / `GeminiInteractionsPath` / `VideoSubmitPath` / `YunwuVideoSubPath` / `AgnesVideoSubmitPath` / `OpenRouterVideosPath` / `ChatPath` / `AnthropicChatPath`），避免真实请求与预览再次漂移
- `buildImageCurl` / `buildVideoCurl` / `buildMJCurl` / `buildChatCurl` 改为按解析出的 provider 选择端点与请求体

## 验证

- `make fmt` / `make build` / `make test`（42 包全绿）/ `make lint`（0 issues）
- 新增**离线**测试（`httptest` 与纯函数，零网络、零付费）：各命令的 `RawJSON` 逐字到达真实端点；flag 路径仍为原 body；`--dry-run` 按 provider 指向正确端点
- 实测 `--dry-run`：openrouter → `/v1/images`、gemini → `/v1/interactions`、ollama → `/api/generate`、zeekai 图生图 → `/v1/images/edits`；video → 各 provider 真实端点；mj → 跟随 `--provider`；chat → `/v1/chat/completions`，原文逐字保留
